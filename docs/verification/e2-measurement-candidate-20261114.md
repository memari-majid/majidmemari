# E2 measurement candidate: local verification

Date: November 14, 2026. This is an implemented **software candidate**, tested with fictional data. It is not a validated assessment, approved amendment, or learning result. `LIVE_RESEARCH_RELEASE` remains `false`; the default research mode remains off. No deployment, participant enrollment, provider call or institutional change was performed for this work.

## Scope and compatibility

Manifest **version 2** opts into the E2 candidate. Version-1 manifests and records retain their original behavior; they are not relabeled or migrated. Version 2 currently accepts E2 only. The fixture is generated by `syntheticE2ResearchManifest()` in `lib/research/config.ts`, with protocol `synthetic-e2-candidate-v2`. Its three parallel task packets and scoring anchors explicitly say they are invented, unvalidated fixtures.

- Allocation: six orders `ABC`, `ACB`, `BAC`, `BCA`, `CAB`, `CBA`, cyclically assigned by a transaction-protected monotonic counter per frozen manifest fingerprint. The order is persisted at enrollment, before any task is revealed. Deletion and withdrawal do not reuse a sequence position. This is counterbalancing, not randomization or proof of equivalent forms. Attrition can unbalance completed records.
- Timing: all three tasks use the same configurable `nominalSeconds` (fixture: 600). First task reveal records `openedAt`; reload cannot restart the clock. Submissions record `elapsedSeconds` and `overNominal`. The UI says explicitly that this is **not a hard cutoff**. Responses are accepted after nominal time and are never silently discarded. Interrupted/overnight sessions need analysis review; elapsed server time is not active working time.
- Optional context: each independent task accepts broad outside-help, interruption and approved-accommodation self-reports; the baseline also asks about prior public rehearsal/demo exposure. Values are `yes`, `no`, `unsure`, `decline`; the last value represents unanswered/prefer-not-to-say and must be treated as unknown. Help categories are coarse and bounded. No names, diagnoses, surveillance, grades or ordinary chat are collected by these fields. These self-reports do not establish formal accommodations or remove confounding.
- Masking: version-2 coder packets have random row IDs, stable random sort order, answer text, task text and rubric anchors. They omit direct participant, occasion, timestamp, form ID/version, assignment and context metadata. Stable order makes a frozen snapshot reproducible. The snapshot ID covers the frozen design, retained denominator and answer rows; new answers or denominator changes invalidate the match.
- Linkage: `export-linkage` is analyst-only and subject to the same grading-release gate as `export-analysis`. It maps row IDs to participant, occasion and form and includes every retained eligible participant ID, including zero-response participants. `export-scoring` never returns that list. Role separation in application code is not a guarantee of independence from the hosting administrator. A task's wording or an identifying answer can still unmask a learner; independent review of the packet is required before distribution.

## Source map

- `lib/research/assessment.ts`: counterbalancing, per-participant form resolution, clock metadata, self-report validation, masked packet/private linkage.
- `lib/research/config.ts`: strict v1/v2 manifest validation and synthetic-only candidate factory. Form fingerprint includes the entire candidate assessment design.
- `lib/research/store.ts` and `service.ts`: durable allocation/task metadata, strict frozen-version matching, answer storage, withdrawal cleanup and exports.
- `lib/research/http.ts`: separate role authorization for linkage. `scripts/research-admin.mjs` exposes `synthetic-e2-manifest` and `export-linkage`.
- `ResearchAnswerForm.tsx`, `ResearchSession.tsx`, `client.ts`: nominal timer, optional context, strict checked session transport. The clock is isolated so its tick does not recreate answer state.
- `scripts/test-research-assessment.mjs`: new synthetic candidate suite.

The companion course repository's `docs/research/tools/score_masked_packet.py` creates pseudonymous coder CSVs and validates the analyst-only join. Its inputs are the matched v2 packet and private linkage; do not feed v2 files directly into the older v1 scoring interface.

- **6 new candidate service tests pass**: schema/version isolation; 30 concurrent enrollments (each order five times, each form ten times at each occasion); persisted reload and nonreused deletion allocation; common timing and retained overruns; strict optional context; masked stable export and private linkage; analyst authorization and source-off gate.
- **40 existing research tests pass**: 19 service, 11 review, 6 HTTP, 4 browser transport. Version-1 assertions now narrow the response type because version-2 export has an intentionally different shape.
- TypeScript (`tsc --noEmit`) and `git diff --check` pass.
- Real local browser-to-API-to-private-file test: Chrome, 390×844, reduced motion. Entered a synthetic participant token, submitted baseline by keyboard, skipped rehearsal through the actual API, submitted immediate and delayed answers, reloaded delayed without resetting its clock, and reached optional final feedback. This verifies the assessment flow, not the pedagogical rehearsal path.
- Stored self-reports and elapsed fields matched the UI actions. Masked and linkage snapshots matched and contained three rows. No browser errors, no horizontal overflow (390/390), and zero external requests. Local synthetic server stopped after verification.
- Companion offline tool consumed these actual exports: both coder sheets created and an unscored summary produced with each occasion `received=1`, `unscored=1`, `mean=null`. No ratings or learning gains invented. Its separate eight tests pass.

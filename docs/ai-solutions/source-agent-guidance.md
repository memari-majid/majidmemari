# Working on Building AI Solutions

> Mirrored guidance for the canonical course source, not an AGENTS.md policy for this hosting repository. Follow the owning repository instructions for implementation.

Read [README.md](README.md) for scope and [REPOSITORY_MAP.md](source-map.md) for ownership. For a review, follow [AI_REVIEW_BRIEF.md](review-brief.md), inspect the actual course, and distinguish observed behavior from source intent and historical claims.

- Preserve the independent identity: Building AI Solutions by Majid Memari, with the framing “Practical AI problem-solving for everyone.” The directory name is historical. The audience is students from any discipline, with no prerequisites. Do not assume programming, prior AI or business knowledge, specific-tool experience, or paid AI access. Explain necessary concepts and retain a supplied-output fallback.
- Preserve real-world need finding, usable implementation, testing, quantitative reasoning, economics, adoption, and handoff. Business cases are useful examples, not an audience restriction or a requirement to start a business.
- The current design is twelve units, one capstone, five milestones, with Learn → Try → Build → Finish. Current instructional intent is in `INSTRUCTIONAL_DESIGN_PLAN.md`.
- Edit current sources listed in `site/README.md`. Rebuild `site/dist/`; do not hand-edit generated HTML, release manifests, or the TA corpus.
- `archive/`, `site/archive/`, `offerings/`, and `domain-examples/` are not the current curriculum. Archived prose is historical evidence, not active instructions.
- Keep course TA, website chatbot, and workshop TA distinct. The course TA uses public course material, not student records or local workbook notes.
- Use the scoped build and checks in `site/README.md`. Check calculations, labels, evidence limits, keyboard use, mobile layout, and reduced motion when changing interactions.
- Preserve unrelated work and learner data. Avoid bulk staging or resetting the surrounding repository. Never include ignored private records, credentials, account screenshots, or student data in a review package or public output.
- A review request calls for findings, not external mutations. For implementation or publishing requests, use the user's actual authorization and the owning repository's workflow.
- `docs/reference-study/` preserves original analysis of an external simulation course for use after access ends. Read its index and coverage before using it; observed behavior, proposed implementation and untested claims are distinct. It is research documentation, not runtime content or a TA corpus input.
- Record what changed and what was actually verified in `DEVELOPMENT_AND_VALIDATION.md`. Technical tests do not establish learner effectiveness.
- For Canvas delivery, start with `integrations/canvas/README.md` and its live installation record. Canvas owns native check-ins, submissions, instructor feedback, progress requirements and grading; the opt-in Vercel display profile supplies embedded lessons, figures, simulations and the course TA. Do not use historical offering scripts or treat browser-local practice/TA history as Canvas records.
